# Needham-Schroeder Public-Key Protocol

This directory contains a ProVerif model of the vulnerable Needham-Schroeder public-key protocol.

## Protocol

~~~text
A -> B : aenc((Na, pkA), pkB)
B -> A : aenc((Na, Nb), pkA)
A -> B : aenc(Nb, pkB)
~~~

`Na` and `Nb` are fresh nonces generated by the initiator and responder.

## Authentication Property

The model uses the following correspondence query:

~~~prolog
query x:pkey, y:pkey, na:nonce, nb:nonce;
  event(endB(x,y,na,nb)) ==> event(beginA(x,y,na)).
~~~

The intended property is:

> If Bob completes a run believing that Alice is his peer, Alice must previously have started the corresponding run with Bob.

## Verification Result

ProVerif reports:

~~~text
RESULT event(endB(x,y,na,nb)) ==> event(beginA(x,y,na)) is false.
~~~

Therefore, the intended authentication correspondence does not hold.

## Lowe Attack

The attack has the following structure:

~~~text
Alice                 Intruder                 Bob

A -> I : aenc((Na, pkA), pkI)

                      I -> B : aenc((Na, pkA), pkB)

                      B -> A : aenc((Na, Nb), pkA)

A -> I : aenc(Nb, pkI)

                      I -> B : aenc(Nb, pkB)
~~~

Alice starts the protocol intending to communicate with the intruder.

The intruder decrypts Alice's first message, forwards its contents to Bob, and relays Bob's challenge back to Alice.

Alice returns `Nb` to the intruder, which can then forward it to Bob.

Bob completes the protocol believing that the peer is Alice, even though Alice did not start that run intending to communicate with Bob.

The attacker does not break public-key encryption. The attack succeeds because message 2 does not bind the responder identity to the protocol run.

## Modeling Note

The handout defines:

~~~prolog
event endB(pkX, pkB, Na, Nb)
~~~

where `pkX` is obtained from message 1.

With an attacker-known private key, an unrestricted `endB` event can also describe a normal run in which Bob communicates directly with a dishonest participant. Such a run would make the correspondence query fail without demonstrating the intended Lowe attack.

To make `endB` represent the authentication claim being tested — Bob completing while believing the peer is Alice — this model records `endB` only when:

~~~prolog
pkX = pkA
~~~

This changes only the event instrumentation, not the Needham-Schroeder protocol messages.

The model also uses:

~~~prolog
fun nonceMsg(nonce) : bitstring.
~~~

to encode a standalone nonce as a `bitstring` payload for message 3, because the model uses a separate `nonce` type while `aenc` accepts a `bitstring`.

# Needham-Schroeder Public-Key Protocol

このディレクトリには、脆弱なNeedham-Schroeder public-key protocolのProVerifモデルが含まれています。

## プロトコル

~~~text
A -> B : aenc((Na, pkA), pkB)
B -> A : aenc((Na, Nb), pkA)
A -> B : aenc(Nb, pkB)
~~~

`Na` と `Nb` は、それぞれinitiatorとresponderが生成するfresh nonceです。

## Authentication Property

以下のcorrespondence queryを検証します。

~~~prolog
query x:pkey, y:pkey, na:nonce, nb:nonce;
  event(endB(x,y,na,nb)) ==> event(beginA(x,y,na)).
~~~

意図するpropertyは、

「BobがAliceをpeerだと信じてrunを完了した場合、AliceがBobを相手として対応するrunを開始していなければならない」

というものです。

## 検証結果

ProVerifは以下を報告します。

~~~text
RESULT event(endB(x,y,na,nb)) ==> event(beginA(x,y,na)) is false.
~~~

したがって、意図したauthentication correspondenceは成立しません。

## Lowe Attack

攻撃の流れは以下です。

~~~text
Alice                 Intruder                 Bob

A -> I : aenc((Na, pkA), pkI)

                      I -> B : aenc((Na, pkA), pkB)

                      B -> A : aenc((Na, Nb), pkA)

A -> I : aenc(Nb, pkI)

                      I -> B : aenc(Nb, pkB)
~~~

AliceはIntruderを相手としてprotocolを開始します。

IntruderはAliceのmessage 1を復号して内容をBobへ転送し、BobのchallengeをAliceへ中継します。

Aliceが返した `Nb` をIntruderがBobへ転送することで、BobはAliceをpeerだと信じてprotocolを完了します。

しかしAliceはBobを相手としてそのrunを開始していません。

攻撃者はpublic-key encryptionを破っていません。message 2にresponder identityがbindingされていないことが原因です。

## モデル上の補足

教材では、

~~~prolog
event endB(pkX, pkB, Na, Nb)
~~~

と定義されています。

ただしattacker-known private keyが存在する状態で無条件に `endB` を記録すると、Bobとdishonest participantが普通に通信したrunでもcorrespondence queryが失敗できます。

今回検証したいのは「BobがAliceをpeerだと信じて完了したLowe attack」なので、このモデルでは、

~~~prolog
pkX = pkA
~~~

の場合だけ `endB` を記録しています。

これはNeedham-Schroederの通信messageを変更するものではなく、検証対象のauthentication claimを限定するためのevent instrumentationです。

また、`nonce` を独立した型として扱いつつ `aenc` が `bitstring` を受け取るため、message 3の単独nonceには、

~~~prolog
fun nonceMsg(nonce) : bitstring.
~~~

を使用しています。
